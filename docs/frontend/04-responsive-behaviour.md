# Responsive Behaviour

One responsive web app serves desktop, tablet and mobile.

## Breakpoint intent
Exact breakpoints may be implemented with the chosen UI system, but behaviour should cover:
- small mobile
- large mobile/small tablet
- tablet
- desktop
- wide desktop

## Public mobile priorities
- booking/search remains prominent
- cards stack cleanly
- date/time controls remain tappable
- WhatsApp/call actions remain easy to reach
- image galleries remain swipe/scroll friendly

## Owner mobile priorities
- pending requests are reachable quickly
- confirm/reject actions are easy to tap but not accidental
- calendar can switch to day view when crowded
- booking detail fits without horizontal scrolling
- add booking/block actions are easy to reach

## Accessibility
- keyboard navigable interactive elements
- visible focus
- sufficient contrast
- labels for form fields
- status not conveyed by colour alone
- alt text for meaningful images
