# V1 Scope Boundary & Future Candidates

This file exists to prevent feature creep during implementation.

## In V1
- Business profile/content
- Vehicle models
- Physical vehicles
- Model-level pricing
- Model/vehicle images
- Customer search
- Date/time-based booking requests
- Private booking-status link without customer login
- Owner confirmation/rejection
- Owner-modifiable requested schedule
- Physical vehicle suggestion/selection at confirmation
- Vehicle reassignment after confirmation
- Offline bookings
- Vehicle blocks
- Business closures
- Availability calculation
- Owner dashboard
- Week/day/month-navigation calendar
- Booking history/statuses
- CSV operational export
- Basic WhatsApp/click-to-chat and optional automation
- Policies/FAQs
- Single admin account
- Security basics
- SEO/local setup
- Production deployment/handover

## Explicitly V2/future
- Customer accounts
- Online payments
- KYC/document capture
- Digital agreements
- Staff/employee roles
- Partner fleet management / provider settlement / 60:40 rules
- Automatic partner sourcing
- Automatic vehicle assignment policies beyond simple suggestion
- Advanced pricing
- Deposits/refunds/penalties
- Maintenance management
- GPS
- Multi-branch
- Full CRM
- Native mobile app
- Sophisticated analytics dashboard
- Multi-model/flexible vehicle preference requests
- Customer self-service booking edits
- Automated reminder campaigns

## Rule for new ideas
When a new requirement appears, classify it as:
1. V1 necessary to make an existing frozen flow correct,
2. V1 optional but small and clearly valuable,
3. V2/future.
Do not expand V1 merely because an edge case can be imagined.
